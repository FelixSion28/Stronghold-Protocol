## 调查与证据

| 问题 | 证据 | 结论 |
|---|---|---|
| 是否可做普通 Git merge | 来源仓库仅携带 payload、补丁、数据变体和安装工具；manifest 基线为原版 0.2.3 | 应按固定版本移植功能，不合并两仓库无关历史，也不运行强制覆盖安装器 |
| 原版补丁与本地差异 | 对 manifest 的 31 个补丁目标计算工作区 UTF-8 / LF SHA-256 | 5 个与基线相同，26 个不同；不同不等于 26 个文本冲突，但安装器的基线校验无法直接通过 |
| 升变的卡池 | 来源 `player/diy.js`、`player/economy.js` 使用 `m.pool`；本地使用 `ps.pool`，`rollPool` 还接受 `player` | 必须适配固定组，升变后的副本借本组术士条目记账，不能重新引入全房共享池 |
| 库存守恒 | 本地 `server/match/invariants.js` 按 `ps.pool` 分组汇总；来源将升变形态映射回术士 | 映射要放入当前分组汇总，覆盖购买、合成、出售、淘汰及跨组赠送；两件新装备服从 D023 库存 |
| 数据开关 | 来源 `server/mod/toggle.js` 用 ON / OFF 快照覆盖 `data/`；OFF 为原版 0.2.3；本地 D022 固定进程运行时目录 | 不能照搬旧快照与运行中热切换。首版选择重建当前基线的数据并重启，页面和模拟使用同一版本 |
| 数据构建 | 本地 DATA / AGENTS 要求从 `tools/build-data.mjs` 生成；公开 MOD 不含其引用的 `tools/local-extract/build-rhodes-mod.mjs` | 需要补可复现的构建路径，不能把来源的生成 JSON 直接覆盖进项目 |
| 本机官方输入 | 本次查看 `.cache/gamedata/` 只有 `audio_data.json` 与 `charword_table.json` | 实施前需要补齐并固定官方表来源；不能声称现有缓存已能离线重建所有游戏数据 |
| 素材合并 | 来源 manifest 列出 51 个素材；assets 差量还删除 `skchr_kalts_1/2/3` 等现有映射 | 只按当前引用核对并合入必要内容，保留当前时装 / 技能映射；素材不进入 Git |
| 升变统计 | 来源 `foldAmiyaQuestResult` 从 result.unitStats 汇总阿米娅伤害，读取 result.healingDone；本地 settle 使用 perPlayer 结果，并分开传递多轮 uniteResults | 必须确认“本人伤害 / 自己编队治疗”的实际统计口径，联防不可借其他人的阿米娅进度，不能重复累加 |

基线相同的 5 个补丁目标为 `public/js/store.js`、`server/match/PlayerState.js`、`server/sim/content/bonds.js`、`server/sim/content/garrisons/battle.js`、`server/sim/content/kits/index.js`。哈希检查只反映文本基线，未进行应用或功能兼容验证。

## 推荐实施步骤（尚未执行）

1. **固定来源和隔离移植。** 保存当前状态，以当前 HEAD 建本地测试分支 / 适合的隔离工作目录；保留未提交的 HTTPS 文档。按上述固定 MOD SHA 获取源码，逐块移植，记录来源和每个冲突的结合方式。素材仅存忽略目录。
2. **建立可复现数据生成。** 在 `tools/build-data.mjs` 增加可选罗德岛内容处理，必要时抽取 `tools/mods/` 辅助模块。干员技能 / 模组投影来自固定官方表；盟约、档位、任务阈值等 MOD 自定义规则单独记录。OFF 从当前 0.2.4 构建，ON 追加内容；不得依靠手改 `data/*.json`，不得使用 0.2.3 OFF 快照。补构建一致性验证，禁止顺带更新全部官方输入造成无关漂移。
3. **移植战斗内容。** 接入罗德岛盟约、干员 kits、召唤物、驻地、两件装备；沿用本地确定性和导入边界。MOD 未启用时内容惰性，不改变现有玩法。明确屏障的作者规则，它并非普通吸收伤害护盾；自定义规则不描述成官方原版。
4. **适配 20 人升变与库存。** 阿米娅从术士升近卫再升医疗，每玩家独立；合成、精锐、装备、召唤物、站位和复制池记账沿用当前机制。将来源的 `m.pool` 改接本地玩家组卡池；shop、特质奖励、卡池、信标等随机通路统一使用换形。保留接收者组返还 / 取副本、私有自选库存、装备组库存与重刷行为。检查 MOD 干员与既有自选 kits 的优先级，避免同 charId 重复注册或遮蔽。
5. **接入客户端与开关。** 私有视图透出任务，增加多特质详情与升变面板，文案补所有语言包；服务端明确校验所属玩家、阶段、当前任务、真实进度和重复领取。复用现有协议校验，新增类型按 compact v1 未知类型回退 / 扩展位传输，不重排布局。时装按升变后 charId 选择合法外观，语音与渲染都验证。首版用停止服务后的 CLI / 构建切换，启动页面只显示状态；不移植运行中写数据的 HTTP 开关。以后若要每房独立开关，需另做数据 bundle 与客户端加载设计。
6. **素材、回归与本地合并。** 补齐新增资源及引用哈希，纳入原统一缓存目录 / ZIP；不引入第二套 SW。在隔离目录通过以下验收后，再合回本地 master，交付来源、提交、测试与回退方法。发布包和线上部署另按实际需求处理。

- **浏览器**：按维护流程使用 Edge，桌面和手机横屏，原有渲染模式、升变前后模型、任务面板、联防与重连；记录真人数量，不把 AI 测试等同真人压测。
